# 非機能要件

## 1. 性能・規模

- **同時利用者数**: [継承] 約10名を想定
- **大量データ閾値**: [継承] 監査ログ対象となるレコード件数の閾値は設定可能とする
  （デフォルト100件以上）
- **応答性能**: [継承] 典型的なマスタデータ操作に対して妥当な応答性能を確保する
  （具体的な目標値は今回も定めない。MasterMeister4同様、質問化を許容する項目）

## 2. セキュリティ

- **標準的なWebアプリケーションセキュリティ対策への準拠**: [継承] security-baseline拡張
  （SECURITY-01〜15）を全面適用する
- **ログ中の機微情報の扱い**: [継承] パスワード・トークン等の機微情報は記録しない
- **アクセス制御が必要な機能の範囲**: [継承] 管理機能全般（ユーザ管理、接続設定、権限設定、
  監査ログ閲覧）は管理者限定。データアクセスは`02-functional-requirements.md`のアクセス
  権限モデルに従う
- **未実装として割り切るセキュリティ機能**: [継承]
  - 監査ログへのIPアドレス記録
  - ログアウト時のセッション継続時間記録
  - 管理者アカウントのMFA（多要素認証）対応（同時利用者10名規模の社内ツールであり、
    管理者を信頼できる小規模チームで運用する前提のため、文書化された例外として適用除外）

## 3. 可用性・耐障害性

- **可用性の目標**: [継承] 特別なSLAは定めない
- **障害時の挙動方針**: [継承] 特別なリトライ・フェイルオーバー要件は設けない
  （resiliency-baseline拡張は適用しない）

## 4. デプロイ・運用

- **デプロイ形態**: `01-tech-and-architecture.md`参照
- **メール送信**: [継承] 開発環境ではMailPitコンテナを用いてメール送受信を確認する。
  本番環境では環境変数経由でSMTP設定を構成可能とする
- **監視・ログ**: [継承] コンテナ環境に適した構造化ログを出力する。本格的な監視ダッシュボードは
  求めず、ログベースの軽量な検知の仕組み（ログイン失敗・認可失敗等のセキュリティイベント）で
  足りるものとする

## 5. ユーザビリティ

- **対応ブラウザ・デバイス**: [継承] デスクトップ利用を中心とし、タブレット等でも大きく崩れない
  程度のレスポンシブ対応を行う（モバイル本格対応は不要）
- **多言語対応**: [継承] 初期リリースから日本語＋英語の2言語に対応する。適用範囲は画面文言・
  フォームラベル・エラーメッセージに加え、招待メール等の通知メール文面、監査ログの表示など
  ユーザに見えるテキストすべて。各機能の実装と同時に組み込む（後からまとめて多言語化する
  手戻りは行わない）
- **アクセシビリティ**: [継承] 特別な準拠基準は定めない（MasterMeister4同様、必要になれば
  個別検討する）

## 6. 保守性・テスト容易性

- **テストカバレッジ方針**: [継承] バックエンドはJUnit5 + Mockito、フロントエンドはVitest +
  React Testing Libraryを標準の組み合わせとする
- **property-based-testing拡張の適用有無**: [継承] 適用する（全面適用）。権限判定・合成ロジック、
  YAML入出力、SQL生成ロジックを重点対象とする（詳細は`00-project-overview.md`）

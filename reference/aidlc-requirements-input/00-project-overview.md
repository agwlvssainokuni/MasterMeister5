# プロジェクト概要

## 1. 開発体制

- **開発体制**: [継承] 単独開発者による初期開発
- **開発方針**: [継承] MVPファーストで段階的に機能を追加する
- **優先順位**: [変更] デザインシステム基盤（自前のUIライブラリ`make-you-chic-ui`を組み込み、
  テーマ設定・共通レイアウトを他機能に先立って確定する。詳細は`01-tech-and-architecture.md`）
  → ユーザ管理 → 対象RDBMSセットアップ → アクセス制御 → データ表示 → その他機能

## 2. スコープ

### 対象に含める範囲
[継承]（詳細は`02-functional-requirements.md`）
- ユーザ登録・認証（管理者招待制、`[変更]`点あり）
- 対象RDBMSセットアップ・アクセス制御（複数接続、多階層権限モデル、YAML入出力、グループ管理）
- マスタメンテナンス（一覧・絞込・編集・作成・削除）
- クエリビルダー・クエリ保存・クエリ実行・クエリ履歴
- 監査ログ閲覧

### 明示的に対象外とする範囲
[継承]
- 招待用パス・トークンパラメータ名のカスタマイズ
- 監査ログへのIPアドレス記録
- ログアウト時のセッション継続時間記録
- 監査ログの保持期間設定・自動削除（パージ）機能
- レジリエンシーベースライン（可用性・DR等の設計時ベストプラクティス）
- モバイルデバイスへの本格対応（レスポンシブの範囲内でのみ配慮、デスクトップ中心）
- CI/CDパイプラインの構築は開発の最終段階に後回し（詳細は`01-tech-and-architecture.md`）

## 3. 拡張機能の適用方針（固定質問）

AI-DLCのRequirements Analysis開始時に必ず聞かれる拡張機能のopt-in可否。
事前に回答を書いておくと1問1答で即決できる。

- **security-baseline（セキュリティベースライン拡張）**: [継承] 適用する
  （管理者アカウントのMFA対応のみ、小規模社内ツール運用を理由に文書化された例外として
  適用除外とする。その他のSECURITY-01〜15は全面適用）
- **resiliency-baseline（レジリエンシーベースライン拡張）**: [継承] 適用しない
  （同時利用者数10名規模・単独開発・MVPファーストという前提のため）
- **property-based-testing（プロパティベーステスト拡張）**: [継承] 適用する（全面適用）
  （権限判定・合成ロジック、YAML入出力、SQL生成ロジックを重点対象とする）

## 4. MasterMeister4からの変更点サマリ

- **ユーザ登録フロー**: 自己申告制（誰でも登録申請可）→ 管理者による招待制に変更
  （詳細は`02-functional-requirements.md`「1. ユーザ登録・認証」）
- **UIコンポーネントライブラリ**: 独自CSS/コンポーネントによるゼロからの構築 → 自前の
  デザインシステムライブラリ`make-you-chic-ui`の組み込みに変更（詳細は
  `01-tech-and-architecture.md`「UIコンポーネントライブラリ」）
- **メールテンプレートエンジン**: 内蔵の自作Mustacheエンジン（`cherry-mustache-core`
  サブプロジェクト）→ 外部公開ライブラリ`java-mustache-processor`の利用に変更（詳細は
  `01-tech-and-architecture.md`「メールテンプレートエンジン」）
- **マスタメンテナンス機能のカスタマイズ**: [追加] MasterMeister4にはなかった、対象RDBMS
  接続ごとのYAML定義ファイルによる表示・入力カスタマイズ（表示ラベル・列順・初期ソート、
  入力ウィジェット種別、列の非表示・読取専用化、簡易バリデーション）に対応する（詳細は
  `02-functional-requirements.md`「3. マスタメンテナンス機能」）
- 上記以外は、技術スタック・アクセス制御モデル・クエリ関連機能・監査ログ・非機能要件を
  含め、MasterMeister4を踏襲する

# Personas (MasterMeister5)

`aidlc-docs/inception/requirements/requirements.md` 6章のロール定義を土台に、User Stories
向けに動機・ゴール・課題を拡充したもの。本プロジェクトのペルソナは以下の2種類のみとする
（story-generation-plan.md Question 4の回答による）。

## ペルソナ1: 管理者（Admin）

- **役割**: 社内システム管理を兼務する担当者。ユーザの入退社に応じてアカウントを招待・無効化し、
  部署やチームに応じて権限を設定する。対象RDBMS接続・スキーマ取込・アクセス権限設定・監査ログの
  管理責任を持つ。
- **ゴール**:
  - 必要な人にだけ必要な範囲のデータアクセスを許可し、それ以外は確実に遮断したい
  - ユーザの入退社・異動に応じて、アカウント状態と権限を素早く・確実に更新したい
  - システムの利用状況・異常の兆候を監査ログから把握したい
  - 権限設定をYAMLで一括管理し、レビュー・バックアップ・複製をしやすくしたい
- **モチベーション**: 単独運用でも権限管理・監査対応の抜け漏れが起きない仕組みが欲しい
  （手作業のミスをシステムで防ぎたい）
- **課題・フラストレーション**:
  - 権限設定がユーザ個別・グループ別に散らばると、実効権限の把握が難しい
  - スキーマ変更のたびにカスタマイズ定義が陳腐化し、気づかず放置されるリスク
  - 招待メールが届かない・トークンが切れた等の問い合わせ対応の手間
- **技術習熟度**: SQL・RDBMSの基礎知識はあるが、専業DBAではない
- **関連エピック**: Epic 1（一部）、Epic 2、Epic 3（カスタマイズ定義）、Epic 5

## ペルソナ2: 一般ユーザ（General User）

- **役割**: 普段DBを直接触らない業務担当者。マスタデータの参照・編集や、SQLの知識に頼らない
  データ抽出を行う。
- **ゴール**:
  - 権限の範囲内で、必要なデータを素早く見つけて確認・修正したい
  - SQLを書けなくても、業務に必要な集計・抽出ができるようにしたい
  - よく使う条件のクエリを保存しておき、毎回同じ作業を繰り返さずに済ませたい
- **モチベーション**: 自分の業務に集中したい。DB操作そのものに時間を取られたくない
- **課題・フラストレーション**:
  - SQLの知識がないため、複雑な条件のデータ抽出が自力でできない
  - 権限がない項目が見えたり触れたりすると誤操作の不安がある（実際には非表示・読取専用化される）
  - パスワードを忘れた・変更したい等、ちょっとした自己解決ができないと管理者への依頼が発生し
    待ち時間が生じる
- **技術習熟度**: SQLの知識はない、またはクエリビルダーによる補助を前提とする
- **関連エピック**: Epic 1（一部）、Epic 3、Epic 4
